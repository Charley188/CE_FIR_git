# 600 MSPS / SSR=2 / 300 tap

ADC/DAC 原始采样率保持 4.8 GSPS，RFDC 内部抽取/插值改为 8 倍。PL 每拍处理两个连续复数样本，数据时钟及算法时钟均为 300 MHz。第一路做校准，第二路保持逐点直通。

当前 BD 将 `clk_300M` 与 `clk_dac0` 接到同一根 `clk_wiz_dac/clk_out1`，算法锁定信号接 `clk_wiz_dac/locked`。PS 派生的 100/10 MHz 控制时钟继续服务 AXI/SPI/时钟芯片初始化。ADC 到算法仍经过跨域 FIFO；算法到 DAC 的 FIFO 使用同一时钟。有限 FIFO 不能校正 ADC/DAC 的持续速率差。

## 数据格式与算法

- ADC I/Q 分离端口各 32 bit：低 16 bit 是较早的样本，高 16 bit 是下一个样本。
- 内部 FIFO 和 DAC 总线为 64 bit，从高到低为 `{Q1,I1,Q0,I0}`。每个有效握手传输两个连续复数点。
- 四个实数 FIR 实现 `I*Cr-Q*Ci` 和 `I*Ci+Q*Cr`；每个 FIR 配置 Single Rate、Sample Frequency=600 MHz、Clock Frequency=300 MHz、单 channel、单 path，自动生成 SSR=2。
- 每个实数 FIR 输入 32 bit，输出 96 bit（每点有效 43 bit、AXI 符号扩展到 48 bit）。结果逐点扩展为 49 bit，再复数加减、算术右移 16 bit、饱和至 signed16。
- 结果队列按双点 beat 保存，读队列、复数加减、饱和分级寄存。输出 FIFO 的 credit 按 beat 计数，包含 FIR 内所有在途输出。
- FIR 使用 Speed 优化，启用系数扇出等流水，生成延迟315拍。首轮 Area 配置的系数到DSP长连线未通过300 MHz建立时间，必须以当前配置的最终报告验收。
- ADC→FIR、FIR→DAC 保留异步 FIFO；有限 FIFO 不能消除板上时钟的长期频差，时钟必须同源锁定。
- ADC域溢出、DAC域欠读先在源域保持事件，再通过三级XPM同步到算法域；重载暂停清除状态。运行/暂停条件先在算法域寄存，再送到各域复位同步器。

## 系数与带宽

保持 300 tap、signed18/Q2.16、非对称、在线可重载；PS 寄存器协议和自然顺序 300 行 MEM 不变。Vivado 2023.2 生成的重载顺序仍为 299..0，维护脚本会检查它。

`matlab/fir_config.m` 统一定义 Fs=600 MHz、默认通带 ±225 MHz（总 450 MHz）、阻带起点 ±270 MHz。可根据指标调整边界，但这不能改变 RFDC 内部滤波器；实际可用带宽需重新测量 bypass。300 tap 的历史跨度约 498.3 ns，不能沿用旧 200 MSPS 下的延迟判断。

主仿真输入为 `input_600_i.txt` / `input_600_q.txt`。MATLAB 添加卷积冲刷零后将长度补成偶数，补齐点也参与逐点比较。DAC beat 文件每行是 `beat_index I0 Q0 I1 Q1`。

更换硬件后需重新生成 bit/XSA、更新 Vitis 硬件平台并重新测量 bypass。MATLAB 生成的 MEM 仍由用户手动复制到 `ps/src/coeff`；本次修改不自动替换 PS 中选定的系数。

## 资源与复现

器件 xczu47dr-ffve1156-2-i：4,272 个 DSP。首轮 Area 配置的独立实数 FIR 综合为每个600 DSP。最终 Speed 配置的完整 sys_top 综合确认 DSP 仍为 2,400（56.18%），相对原来约 28% 的占用约 2 倍；LUT 14.17%、FF 20.27%、BRAM 3.70%。速度优化主要增加寄存器，综合资源足够，最终时序以布局布线报告为准。

历史 SSR600 版本曾完成布局布线，WNS=+0.025 ns、WHS=+0.010 ns；该结果不代表当前 DAC 同源时钟与诊断版本的最终时序。当前版本的验证边界和复现入口见 [VALIDATION.md](VALIDATION.md)。

- `docs/maintenance/enable_ssr600.tcl`：关闭 GUI 工程后更新共享 FIR IP 和 ADDA BD/Wrapper，并检查顶层；`FIR_ONLY` 参数仅更新 FIR。
- `validation/run_online.tcl`：真实 IP 的复数卷积、全 300 tap、边界系数、CRC/重载测试。


最终验证结果见 `docs/VALIDATION.md`。历史 RFDC24 文档和报告不能作为本配置的验证证据。
