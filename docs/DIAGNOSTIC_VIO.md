# 600 MSPS 第一通路 VIO 诊断版

本版本在同一个 bit 内比较 FIR 与硬件旁路；两者均使用第一路 ADC/DAC、相同 I/Q 排列和同一组异步 FIFO。第二路不是本次测量的替代通路。

## 上板操作

1. 在主ADDA工程完成综合、布局布线、时序检查后生成BIT和对应LTX，再配套加载。保持原 PS 启动和 300 tap 系数加载流程；本次没有改 PS 源代码。
2. 等 PS 完成加载，打开 Hardware Manager 中的 `stream_mode_inst` VIO。
3. `probe_out0`（`diagnostic_mode_request`）：0 = FIR，1 = 硬件旁路。上电默认为 0。
4. `probe_in0[0]` = 已生效的模式；bit 1 = path_running；bit 2 = update_hold。切换后等待 bit 0 等于请求、bit 1 为 1、bit 2 为 0，再开始 VNA 扫描。还应确认 DAC ILA 中 valid 和 FIFO 水位已稳定，不要在切换瞬态采集。
5. 先以模式 1 测量同一物理链路，再切到模式 0 测量单位冲激 FIR。保存模式、系数版本、NCO 频率和故障计数。换模式或重载会清空故障记录，切换前先保存 ILA 数据。

运行期间的模式请求在完整系数镜像已经运行后受理。首次加载的 START 命令会采样当前 VIO 请求，因此也可在加载前选择模式。切换流程：暂停、复位通路 FIFO/FIR、等待 quiet 至少 32 个算法时钟、切换模式、重新加载保留的系数、内部配置提交、恢复运行。不是无缝切换；DAC 在无有效数据期间输出零。两种模式仍有不同的有效信号延迟。

FIR 的 CONFIG 握手不等于系数已经应用。每次启动/重载后，内部给 FIR 送一个全零双点拍，丢弃对应输出，确认配置已应用后才开放 ADC/DAC 通路并报告 RUN。此过程不依赖外部 ADC valid，也覆盖首次加载前已经选择旁路的情况。运行期间 ADC 旁路数据不经过 FIR，也不受其 ready 控制；内部零拍不会进入 DAC 或改变有效样点序列。依据：[AMD PG149 RELOAD Channel](https://docs.amd.com/r/en-US/pg149-fir-compiler/RELOAD-Channel)。

## ILA 探针

每个新增 ILA 都是 4096 深度、128 bit 单探针，并在对应本地时钟采集。ILA 配置有一级输入寄存器，同一探针内部字段保持对齐。不同 ILA 捕获不能直接按同一行视为同一时刻。

| 实例 | probe0 位 | 含义 |
|---|---|---|
| diag_adc_inst | 63:0 | ADC 打包数据，低到高 I0/Q0/I1/Q1，每个 16 bit |
| | 95:64 | ADC 上游有效而输入 FIFO 不 ready 的累计拍数，饱和计数 |
| | 96 / 97 | m00 / m01 valid |
| | 98 / 99 | 输入 FIFO ready / ADC 压力事件 |
| | 100 / 101 | 输入压力或 XPM overflow 锁存 / ADC reset 已释放 |
| diag_alg_inst | 63:0 | 输入 FIFO 在算法域的输出数据 |
| | 69:64 | 输入 FIFO 水位，单位为 64 bit beat（两个复数点） |
| | 70 / 71 / 72 | FIR 输出 valid / 输入 FIFO valid / 输入 FIFO ready |
| | 73 / 74 / 75 | fir_stream_started / 算法 reset 已释放 / 实际旁路模式 |
| | 76 | FIR 配置提交已完成 |
| diag_dac_inst | 63:0 | 实际送到 RFDC 的数据，无效期间为零 |
| | 95:64 | 启动后 DAC 断粮累计拍数，饱和计数 |
| | 101:96 | DAC FIFO 水位，单位为 beat |
| | 102 / 103 / 104 | DAC valid / DAC ready / 当拍断粮 |
| | 105 / 106 | 断粮或 XPM underflow 锁存 / DAC reset 已释放 |

断粮定义：DAC 已启动、RFDC ready、但 FIFO 无有效数据。仅零填充不会恢复丢失的数据，也不能使断粮情况下的 VNA 测量有效。输入压力监测在输入 FIFO 首次 ready 后启用，排除 FIFO 正常复位恢复期间的误报。输入压力表示不能持续接收 ADC，不直接等同于已确认 RFDC 内部丢样；仍需读取 RFDC 自身 FIFO 状态。

推荐先触发 `diag_dac_inst/probe0[104] == 1`，再观察水位变化和计数。健康连续输入时，断粮计数应为零。改变输入频率时保持 ADC 数字流连续；关闭模拟信号并不等于停止 ADC valid。

## VNA 对比解释

- 保持同一物理连接、RFDC/NCO、VNA 扫频范围和功率。模式 0 使用单位冲激系数，模式 1 使用硬件旁路。
- 健康理想通路中，两种模式的幅频响应应接近，但相位斜率和总延迟会不同；不应直接将相位差当作幅频失真。
- 若只有模式 0 异常，优先检查 FIR 路径、实际生效系数及其流控。若两者都有同样凹口，继续检查共享的样点排列、RFDC 配置/内部状态、时钟和模拟链路，不能仅凭这一项就断定是模拟问题。
- 若出现输入压力或 DAC 断粮，先处理持续供数问题；该次响应不宜直接用于计算补偿系数。

## 兼容的 AXI 状态扩展

相对于现有系数控制器基地址：

| 偏移 | 含义 |
|---|---|
| 0x08 bit 5 | 原错误标志增加运行期故障锁存 |
| 0x0C 低 8 bit | 运行期故障时为 8，其他情况沿用原错误码 |
| 0x3C bit 0 | 生效旁路模式（同步到 AXI 域） |
| 0x3C bit 1 | 运行期故障锁存（同步到 AXI 域） |
| 0x40 | 诊断 ABI 标识 0x44473031，ASCII DG01 |

运行期故障不自动停止通路，以保留水位/计数证据；RUN 表示启动状态，不表示数据无故障。VIO 切换或重新加载会清除本轮故障。自动模式切换的完成快照与软件命令回复区分，避免错误清除正在等待的软件命令 BUSY。

## 本次范围和验证

RFDC 仍为 4.8 GSPS、ADC /8、DAC x8，600 MSPS/SSR2。算法、ADC、DAC 时钟来源保持原状，以便先测出是否存在速率差；本版不声称解决板级参考时钟关系。

主工程已经包含诊断RTL、ILA和VIO配置，无需临时测试工程。当前DAC同源配置的验证边界见 [VALIDATION.md](VALIDATION.md)。
